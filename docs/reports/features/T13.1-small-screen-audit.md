## 6. Hasil testing
- Uji perangkat: Sony Xperia XZ (F8331), Android 8.0, **build debug** dari `main` `2988f76`. 320 dp = `wm density 540`, 360 dp = density bawaan.
- Kombinasi: 320 dp id-gelap / en-gelap / id-terang, 360 dp id-gelap / en-gelap; ±230 screenshot, 22 dari 25 `*Screen.kt` + dialog + onboarding langkah Sambutan, 1, 2 (emulator Pixel 9a bersih, 320 dp).
- Setiap screenshot diperiksa visual, plus cek otomatis dari `uiautomator dump` (keluar layar, teks bertumpuk/menempel, target sentuh < 48 dp).
- Crash / StrictMode / LeakCanary: tidak ada temuan. Mengubah density 320 ↔ 360 dp di tengah rekaman tidak menghentikan rekaman.

## 9. Risiko & bug yang diketahui
1. Dua bug di luar ukuran layar dicatat (audit §6): format angka sesaat memakai titik setelah activity dibuat ulang; tab Setelan tidak kembali ke daftar dari sub-layar. Keduanya P3, belum diverifikasi lebih jauh.
2. Ringkasan ride membuka keyboard otomatis (audit #8): tidak disengaja (kode tidak meminta fokus), dicek di T13.4.
3. `wm density` ≠ HP 320 dp asli (font/inset bisa beda); uji akhir di HP kecil asli tetap diperlukan (DoD Fase 13).

## 10. Cara menguji (untuk pemilik proyek)
1. `adb shell wm density 540` (Sony XZ → 320 dp), buka Rute tanpa rute: teks kosong terpotong (P2 #1).
2. Riwayat › Aktivitas: "0,00 km" menempel ke kolom RIDE (P2 #2).
3. Mulai ride → PAUSE: tombol SELESAI terpotong di bawah (P2 #3).
4. Kembalikan: `adb shell wm density reset`.
