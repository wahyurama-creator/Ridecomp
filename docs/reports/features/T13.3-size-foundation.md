# Feature Report — T13.3: Fondasi ukuran `Regular`/`Compact`

**Tanggal:** 2026-11-21
**Branch:** `feature/T13.3-size-foundation`
**Status:** Selesai 2026-11-21 (compare di HP pemilik, §11)

## 1. Ringkasan
Fondasi Fase 13: kelas lebar `WindowWidthClass` (COMPACT di bawah 360 dp) dihitung sekali di `RideCompTheme`, dan ukuran yang boleh berubah di layar kecil ada di `AdaptiveDimens` (`RideCompTheme.dimens`). Di 360 dp ke atas semua nilai sama persis dengan sebelumnya. Di 320 dp: padding samping kartu 16 → 12 dp dan kalimat layar kosong 22 → 18 sp. Layar kosong/galat (`MessageState`) sekarang bisa di-scroll bila teksnya tidak muat (audit T13.1 P2 #1, Rute kosong).

## 2. Perubahan per lapisan

## 8. Penyimpangan dari spesifikasi / RULE-EXCEPTION
- Rencana menulis "`RideCompDimens` → data class + `Regular` + `Compact`, migrasi bertahap". Dipilih `AdaptiveDimens` terpisah dengan token yang benar-benar berubah saja (D-143): tanpa migrasi 120 token dan `Regular` identik secara konstruksi.
- "Layar yang membaca `LocalConfiguration`/`BoxWithConstraints` untuk lebar dialihkan": setelah dicek, tidak ada yang membaca lebar untuk tata letak (lihat D-143 butir 5), jadi tidak ada yang dialihkan.
- Bukti compare menunggu perangkat (syarat T13.2).

## 9. Risiko & bug yang diketahui
1. Tampilan 320 dp belum dilihat di perangkat: padding kartu 12 dp memengaruhi semua kartu di layar < 360 dp.
2. `BoxWithConstraints` di `MessageState` menambah satu subkomposisi untuk layar kosong (bukan layar ride; dampak kecil).

## 10. Cara menguji (untuk pemilik proyek)
1. HP uji/emulator dengan build debug dari `49f9141`: `scripts/screens/capture.sh base-id-dark`.
2. Pasang build `main` terbaru: `scripts/screens/capture.sh t13-3-id-dark` → `python3 -I scripts/screens/compare.py build/screens/base-id-dark build/screens/t13-3-id-dark` harus "All screens identical".
3. `scripts/screens/capture.sh t13-3-320 320`: Rute kosong kini bisa di-scroll, kartu sedikit lebih lebar isinya.

## 11. Uji perangkat (2026-11-21)
realme RMX3830, baseline `base-id-dark` (APK `49f9141`) vs `t13-3-id-dark` (APK `main` dengan T13.3):

| Lebar | Hasil `compare.py` |
|---|---|
| 412 dp | 25/25 identik (Beranda diambil ulang: pengambilan pertama tertutup layar "Security test" ColorOS setelah install) |
| 390 dp | 25/25 identik (sama, Beranda diambil ulang) |
| 360 dp | **25/25 identik** |
| 320 dp | 10 layar berubah, sesuai rencana: Setelan, Sensor, Rute, Beranda, Persiapan ride, Backup, Tampilan, Bahasa, Rencana latihan, Sepeda (padding kartu 12 dp; kalimat layar kosong 18 sp) |

Dilihat dengan mata di 320 dp: kartu "HP saya mematikan app" dan baris "Keselamatan & kontak darurat" tidak lagi turun 2 baris berlebihan (audit #10 sebagian), teks kartu tips Rute lebih lebar (audit #12), kalimat Rute kosong lebih ringkas. Tidak ada teks yang terpotong baru.

Target sentuh (`targets.py`, 56 dp) di 320 dp vs 360 dp: **tidak ada yang memburuk**. Yang < 56 dp sama di kedua lebar dan sudah ada sebelumnya: tab Riwayat (48 dp), chip di Profil aktivitas (48 dp), baris Bahasa (48 dp), kotak halaman data selebar 47 dp; dicatat di audit §3a.

Catatan: HP ini setinggi 711 dp di 320 dp (Sony XZ: 569 dp), jadi temuan audit yang bergantung tinggi layar (Rute kosong P2 #1, tombol SELESAI, Sambutan) tidak muncul di sini; T13.4/T13.5 menguji juga dengan `wm size` setinggi Sony.
