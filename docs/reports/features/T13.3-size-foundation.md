# Feature Report — T13.3: Fondasi ukuran `Regular`/`Compact`

**Tanggal:** 2026-11-21
**Branch:** `feature/T13.3-size-foundation`
**Status:** Kode selesai dan di-merge; **bukti compare 412/390/360 dp dan cek visual 320 dp menunggu perangkat uji** (task belum dicentang)

## 1. Ringkasan
Fondasi Fase 13: kelas lebar `WindowWidthClass` (COMPACT di bawah 360 dp) dihitung sekali di `RideCompTheme`, dan ukuran yang boleh berubah di layar kecil ada di `AdaptiveDimens` (`RideCompTheme.dimens`). Di 360 dp ke atas semua nilai sama persis dengan sebelumnya. Di 320 dp: padding samping kartu 16 → 12 dp dan kalimat layar kosong 22 → 18 sp. Layar kosong/galat (`MessageState`) sekarang bisa di-scroll bila teksnya tidak muat (audit T13.1 P2 #1, Rute kosong).

## 8. Penyimpangan dari spesifikasi / RULE-EXCEPTION
- Rencana menulis "`RideCompDimens` → data class + `Regular` + `Compact`, migrasi bertahap". Dipilih `AdaptiveDimens` terpisah dengan token yang benar-benar berubah saja (D-143): tanpa migrasi 120 token dan `Regular` identik secara konstruksi.
- "Layar yang membaca `LocalConfiguration`/`BoxWithConstraints` untuk lebar dialihkan": setelah dicek, tidak ada yang membaca lebar untuk tata letak (lihat D-143 butir 5), jadi tidak ada yang dialihkan.
- Bukti compare menunggu perangkat (syarat T13.2).

## 9. Risiko & bug yang diketahui
1. Tampilan 320 dp belum dilihat di perangkat: padding kartu 12 dp memengaruhi semua kartu di layar < 360 dp.
2. `BoxWithConstraints` di `MessageState` menambah satu subkomposisi untuk layar kosong (bukan layar ride; dampak kecil).
