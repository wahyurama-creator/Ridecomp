# Feature Report — T11.2a: StrictMode saat peta dibuat

**Tanggal:** 2026-11-19
**Branch:** `fix/T11.2a-map-strictmode`
**Status:** Diterima (pemilik: "perbaiki dulu sebelum lanjut"; memilih memuat library peta saat peta akan tampil)

## 1. Ringkasan
Uji T11.2 menemukan pelanggaran StrictMode di thread utama saat peta dibuka. Jejak stack lengkap direkam dengan `penaltyListener` sementara (lokal, tidak di-commit), karena ColorOS memotong jejak di log. Ditemukan dua sumber:
1. **±320 ms, sekali per proses aplikasi:** `MapLibre.getInstance()` memuat library native `libmaplibre` (`System.loadLibrary`, baca disk) di thread utama. Terjadi pada peta pertama yang dibuka di layar mana pun.
2. **±8 ms, setiap peta dibuat:** `MapView(context)` membaca atribut tema dari resource (`MapLibreMapOptions.createFromAttributes`). Dengan LazyColumn (T11.2), ini terulang setiap kali peta di-scroll kembali.

Perbaikan: keduanya kini dikerjakan di dispatcher IO sebelum `MapView` dibuat. Selama persiapan, kotak peta kosong dengan ukuran sama, jadi tata letak tidak bergeser.

## 2. Perubahan per lapisan
| Lapisan | File/kelas | Keterangan |
|---|---|---|
| UI bersama (`:ui-common`) | `map/MapEngine.kt` (baru) | `LocalMapIoContext` (dispatcher dari aplikasi, CO-03). `MapEngine.loadLibrary`: `LibraryLoader.load()`, yang punya penanda "sudah dimuat" sendiri sehingga panggilan berikutnya langsung kembali. `MapEngine.prepareView`: library + `MapLibreMapOptions` |
| UI bersama (`:ui-common`) | `RouteMap` | `produceState` menyiapkan opsi di IO, lalu `MapView(context, options)`; sebelum siap tidak ada `MapView` |
| UI bersama (`:ui-common`) | `rememberRouteSnapshot` | Snapshotter dimulai setelah library siap |
| App | `MainActivity` | Menyediakan `LocalMapIoContext` dari `DispatcherProvider.io` (Koin) |
